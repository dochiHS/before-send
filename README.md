# 보내기 전에 — 개인정보 한 번 더 보기

메일·메신저·문서를 보내기 전에 글을 붙여 넣으면, 그 안에 섞인 **카드번호·주민등록번호**를 찾아 이유와 함께 알려 주고 번호를 가린 글을 만들어 줍니다.

- ALEPH 마지막 과제 B
- 근거 논문: 「체크섬 검증이 개인정보 탐지 규칙의 오탐과 미탐에 미치는 영향 — 카드번호 Luhn 검사와 2020년 개편 이후 주민등록번호를 중심으로」 (ALEPH 과제 10)
- 공개 주소: https://dochihs.github.io/before-send/

## 실행 방법

1. 이 폴더(또는 ZIP을 푼 폴더)에서 `index.html`을 더블클릭해 Chrome·Edge로 엽니다.
2. 설치할 것, 서버, 로그인, 인터넷 연결이 필요 없습니다. (글꼴만 인터넷이 있으면 받아 오고, 없으면 기본 글꼴로 보입니다.)

## 사용자가 할 일 세 가지

1. **붙여넣기** — 보낼 글을 1번 칸에 붙여 넣거나 「예시: 고객 환불 메일」을 누릅니다.
2. **확인** — 2번 「검사 결과」에서 찾은 번호와 이유, 걸러 낸 숫자와 이유를 봅니다.
3. **복사** — 3번 「가린 글 복사」를 눌러 번호가 가려진 글을 복사해 보냅니다.

## 논문 결과를 어떻게 쓰나요

| 대상 | 논문 결과 | 앱의 규칙 |
|---|---|---|
| 카드번호 | Luhn 추가 시 오탐 100% → 11.7%, 미탐 0% | 16자리 모양 **+ Luhn 통과**만 카드번호로 알림 |
| 주민등록번호 | 날짜·성별 검사만으로 오탐 100% → 39.0%, 미탐 0% / 옛 검증번호를 필수로 쓰면 2020년 10월 이후 번호의 90.8%를 놓침 | 13자리 모양 **+ 생년월일·성별 자리**까지 필수, 검증번호는 맞으면 "확실", 안 맞으면 "확인 필요"로 표시하는 **참고용** |

판정 규칙은 논문 재현 패키지의 `scripts/rules.py`(C2·R2·R3)를 JavaScript로 그대로 옮겼습니다. 앱 안의 「논문 근거 보기」를 펼치면 지금 붙여 넣은 글에 다섯 규칙(C1·C2·R1·R2·R3)을 각각 적용한 건수가 논문 수치와 나란히 나옵니다.

## 데이터와 비밀값

- 붙여 넣은 글은 브라우저 안에서만 검사하고 어디에도 보내거나 저장하지 않습니다.
- 예시 글의 카드번호(4111 1111 1111 1111)는 카드사가 시험용으로 공개한 번호이고, 주민등록번호 모양 숫자는 손으로 적은 예시입니다. 실제 개인정보는 없습니다.
- 주민등록법 제37조를 지키기 위해 번호를 **만들어 내는** 기능은 넣지 않았습니다. 찾고 가리는 기능만 있습니다.
- API 키·비밀값을 쓰지 않으므로 **필요한 환경 변수는 없습니다.**

## 잘못된 입력

빈 글, 공백만 있는 글, 기호만 있는 글, 이모지, 10만 자가 넘는 글(앞 10만 자만 검사하고 안내 표시), HTML 태그가 섞인 글을 넣어도 멈추지 않습니다.

## 한계 (논문과 같음)

- 16자리 카드만 봅니다(15자리 카드는 못 찾음).
- 숫자 검사만으로는 오탐이 남습니다(카드 약 12%, 주민 약 39%). 그래서 걸린 항목마다 이유를 보여 주고 최종 판단은 보내는 사람에게 맡깁니다.
- 전화번호·계좌번호·여권번호는 검사하지 않습니다.
